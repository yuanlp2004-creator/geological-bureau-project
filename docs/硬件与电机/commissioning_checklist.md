# 现场核对清单

本清单汇总现有材料无法确认的现场事实，不表示每项都必须重新测量，也不表示所有项目都由电机 API 开发者负责。已有交付机验证记录可直接作为起点，再核对是否仍与现机一致。

## 先要到可以复现的有效配置

优先确认 RtuMotor 是否曾在交付仪器上成功控制光栅，并取得当时的软件配置、驱动器设置、开机/设零/转角步骤及至少一组目标角度与脉冲位置记录。成功运行记录能帮助确认通信和动作链，但不能单独证明全范围精度、重复性或异常处理已验收。

## 代码参数审计（汇报用）

下表中的“默认值”来自独立 API 的 `MotorProfile`。配置对象在一次连接会话中不可变，但可在下一次连接时显式替换，因此不能把这些值称为永久写死。模板中的 COM3 来自随包 `RtuMotor.Opt`；其 `[Motor]` 段为空，所以旧程序实际回落到 Delphi 默认值。

| 参数/假设 | 当前默认或固定规则 | 来源与运行时行为 | 若与真机不符的影响 | 现场处理优先级 |
|---|---|---|---|---|
| `transport` | `simulator` | API 默认；可在连接时改为 `serial` | 漏配时软件会报告模拟运动成功，但真机完全不动 | 最高：交付配置必须显式为 `serial` |
| `port` | API 默认 `None`；模板 `COM3` | COM3 来自旧 `RtuMotor.Opt`；串口模式必须显式填写 | 连接失败，或误连同机其他串口设备 | 最高：现场枚举并核对转换器序列号 |
| `address` | `1` | 旧 Delphi `DefRtuAdr=$01`；连接时可改 | 无响应；多站总线上还可能命令错误站点 | 最高：核对驱动器站号 |
| `baud_rate` | `19200` | 旧程序固定选择 `Bauds[1]`；API可从五档中选择 | 无法解析回包 | 最高：核对当前驱动器通信设置 |
| `resolution` | `76800 MMS/齿` | 旧 Delphi 默认；驱动器连接时会读回并与配置比较 | 不符时连接被拒绝；若配置被错误改成同样错误值，会影响 MMS 换算 | 最高：读驱动器并记录 |
| `motor_teeth` | `100` | 旧 Delphi `DefTeeths`；驱动器不能直接证明此机械量 | 计算出的 `pulse_length`、每圈关系及角度可能整体按比例错误 | 最高：核对机构或原有效配置 |
| `pulses_per_motor_rev` | `640000 pulse/rev` | 旧 `StepPerTurn` 默认；可配置，不能仅凭位置寄存器证明 | 目标角度按固定比例放大或缩小，可能撞限位 | 最高：核对细分、驱动设置和实测一圈 |
| `gear_ratio` | `1.0` | 新 API 为适配传动机构增加的假定；旧测试程序没有此参数 | 有减速、增速或齿轮传动时，角度按比例错误 | 最高：核对电机—光栅传动比 |
| `direction` | `+1` | 沿用旧程序“正角度=正脉冲”的行为；可设 `-1` | 转向相反，可能直接驶向机械限位 | 最高：低速小步进验证 |
| `zero_pulse` | `0` | 新 API 默认假定；驱动器没有机械原点证明 | 所有绝对角度存在固定偏移；断电或设零后可能失效 | 最高：明确0°定义、建立方式和重启规则 |
| `min_angle_deg` / `max_angle_deg` | `0°..90°` | 旧界面限制为0到四分之一圈；连接时可配置 | 范围过大可能撞限位，过小会拒绝有效波段 | 最高：取得安全机械范围和工作范围 |
| `backlash_pulses` | `0`，允许0..3200 | 旧界面默认0、上限3200；可配置 | 为0可能导致反向定位重复性差；数值/方向不对会越调 | 高：双向重复定位实测 |
| `move_timeout_s` | `30 s` | 新 API 默认；可配置 | 过短产生假故障并STOP，过长延迟故障处理 | 高：按最大行程和最低速度实测 |
| `stop_timeout_s` | `3 s` | 新 API 默认；可配置 | 过短会把实际停止记为未确认，过长会延迟安全处置 | 高：测最坏负载停机时间 |
| `poll_interval_s` | `0.1 s` | 新 API 默认；可配置 | 影响到位发现延迟和总线负载，也会影响BusWDT | 高：结合看门狗和采集周期验证 |
| `settle_time_s` | `0.2 s` | 新 API 默认；可配置 | 过短可能在光栅仍振动时采集，过长降低效率 | 最高：用光谱/位置重复性确定，不只看寄存器 |
| `calibration_id` / `motion_verified` | 空 / `false` | 安全门；串口写运动前要求人工确认并显式填写 | 能防止误用默认值，但不能证明填写内容真实 | 最高：关联正式标定记录，不能只改为true |

以下规则目前确实固定在代码中，运行时不能通过 `MotorProfile` 改变。只有确认交付驱动器与随包 AgeMotion 手册兼容时才能继续沿用。

| 固定项 | 当前实现 | 可能不适用的情况及影响 | 应核对材料 |
|---|---|---|---|
| 串口格式 | 8数据位、偶校验、1停止位（8E1），无软/硬流控 | 真机为8N1、8O1或需RTS控制RS485收发方向时完全无法通信 | 驱动器设置、转换器型号、接线图 |
| 波特率集合 | 9600/19200/38400/57600/115200 | 固件使用其他速率时API会在打开串口前拒绝 | 驱动器通信参数 |
| RTU站号范围 | 1..247，单个服务控制一个站点/一根轴 | 广播、网关映射或多轴联动不能直接使用 | 总线拓扑和轴数 |
| RTU寄存器、宽度、功能码、控制字、端序和CRC | 完全按随包 AgeMotion 手册及 `uRtuMotor.pas` 固定 | 驱动器型号/固件协议不同会导致拒绝、误读或错误动作 | 铭牌、固件版本、对应协议手册，最好提供抓包 |
| 帧间隔 | 串口交易后固定约30 ms | 转换器/驱动器需要更长恢复时间时出现间歇性超时；更短需求只影响效率 | 连续读写压力测试和厂商最小间隔 |
| 打开串口方式 | 打开后清空输入缓冲；未提供可配置的上电稳定等待和手动RS485方向控制 | USB转换器枚举慢、驱动器刚上电或非自动换向时首帧失败 | 转换器与开机流程 |
| 电流允许区间 | `current_set` 20..100（0.20..1.00 A）；`current_low` 30..100% | 来自旧界面；实际电机额定电流超过1A时会拒绝有效设置或拒绝运动 | 电机铭牌、驱动器CurrentMin/Max和现用参数 |
| 速度允许区间 | `velocity_set` 200..1000；`velocity_start` 5..50 | 来自旧界面，明显窄于手册寄存器范围；不同负载可能需要更低启动或更高运行值 | 当前驱动器导出、失步和时间测试 |
| 间隙补偿方向 | 只在目标小于当前位置时先越过目标，再从同一方向逼近 | 机构反向、双向间隙不对称或非线性传动时补偿错误 | 机械方向和双向实测曲线 |
| 角度换算模型 | `pulse = zero + angle × pulses_per_rev × gear_ratio × direction / 360`，假定线性 | 凸轮、丝杆/连杆非线性或角度定义不是电机轴线性比例时，全程角度不准 | 机构图及多点角度—脉冲标定 |
| 到位判据 | 目标位置精确相等、实时速度为0，并持续稳定 `settle_time_s` | 开环寄存器可能只代表指令位置，不能证明光栅真实到位；伺服可能允许非零跟随误差 | 驱动类型、编码器反馈、定位验收方法 |
| STOP确认判据 | 速度0、位置稳定且当前位置等于驱动器停止后的目标位置 | 某固件STOP不重写目标、速度零值定义不同或通信中断时无法确认 | STOP寄存器抓包和最坏工况测试 |
| 参考标记 | Control位7作为本会话参考/重启标记 | 固件对位7语义不同会误判参考有效或失效 | 对应固件手册和重启实测 |
| 回零/硬限位 | 未实现传感器寻零、寻限流程；角度仅受软件上下限约束 | 有原点/限位传感器且交付要求自动恢复时功能不足 | 传感器端口、电平、搜索方向和验收步骤 |

真实连接会读取 `resolution`、`pulse_length`、`current_min/max`、当前电流/速度、`velocity_factor`、`input_type`、`BusWDT` 和通讯滤波等寄存器，所以这些读值本身不是用模拟器默认值冒充真机值。不过当前 API 只对其中一部分做一致性或范围检查；读到了数值也不等于已经证明它适合实际电机和光栅机构。

模拟器还固定使用 `pulse_length=12`、`current_min=20`、`current_max=100`、`current_set=100`、`current_low=50`、`velocity_set=640`、`velocity_start=16`、`velocity_factor=20`、`BusWDT=65535`、`input_type=0` 和 `velocity_filter_com=0`。其中电流、速度和几何默认值来自旧 RtuMotor 或与其一致，`velocity_factor` 等只是测试夹具值。这些数值用于离线测试，真实串口连接不会把它们自动写入驱动器，也不能作为交付机参数记录。

## 按责任与用途核对

| 范围 | 需要确认 | 用处 |
|---|---|---|
| 电机 API 通信 | 驱动器型号与协议版本、COM 口、USB/RS485 接法、站号、波特率 | 选对通信实现并连通设备 |
| 电机 API 角度定位 | 每圈脉冲数、齿数与细分、传动比例、正方向、0°参考和有效角度范围 | 把目标光栅角度换算成可执行坐标 |
| 电机 API 运动与恢复 | 现用电流/速度/滤波、间隙及补偿空间、看门狗、断线和重启后的行为 | 确定运动、停止及恢复规则 |
| 有条件的扩展功能 | 若要自动寻原点或使用硬限位：传感器、端口、有效电平、搜索方向及步骤 | 设计现有材料未完整提供的回零/限位流程 |
| 上层采集与光学 | 角度—波长—像素标定、转动和曝光时序、到位后等待、异常时电弧与 CCD 停止规则 | 自动选波段、调度、采集与分析；需要团队协作 |
| 仪器与验收 | CCD-I/CCD-III、改造状态、定位精度与重复性、运动/停止时间及测量方法 | 明确适配模式和验收边界 |

寄存器可读取的设置应尽量读回核对；机械传动、光学零点、传感器布置和实际精度不能仅靠源码默认值推断。铭牌、配置导出和现行操作记录比零散口述更便于复现。

## 实施顺序

先用模拟器验证软件调用，再用现场有效配置只读发现，核对角度换算和参考位置后开展受控定位测试，最后与采集、电弧控制联合验证。独立 API 参数模板可查本机归档中的 `StandaloneMotorApi/startup_and_integration.md`。GeoSpectrum 当前接入与证据见 [硬件与电机索引](README.md)。
