# 前端架构导读

## 1. 入口与职责分布

前端入口是 [`main.tsx`](../../app/frontend/src/main.tsx)，负责加载样式入口并挂载根组件。R5 后 [`App.tsx`](../../app/frontend/src/App.tsx) 仅保留认证状态（82 行），[`layout/WorkspaceApp.tsx`](../../app/frontend/src/layout/WorkspaceApp.tsx) 保持原来的跨页面状态与分派逻辑。

主要文件职责：

| 文件 | 职责 |
|---|---|
| `App.tsx` | 首次管理员/登录状态与认证恢复 |
| `layout/` | WorkspaceApp、Sidebar、Header、页面状态与 TaskLayout |
| `pages/` | 按业务组织的页面及单页专用组件 |
| `api/`、`platform/` | 按业务组织类型和请求；共享传输、Tauri 运行时与文件能力单独归位 |
| `navigation.ts` | 从后端 capability 清单生成导航，处理权限可见性和运行期可用性 |
| `components/NumericInput.tsx`、`components/numericInputModel.ts` | 允许空编辑态并统一范围、步长、回车和取消行为的数值输入 |
| `components/SpectrumPlot.tsx` | 谱图显示、坐标、光标、锁线、平移和框选 |
| `styles/index.ts` | 按原顺序加载组件、页面和全局样式；global.css 为全局基础 |
| 独立 `*Page.tsx` | 设备、色散、采集、硬件、汞灯、分析、后处理、报告、维护和帮助页面 |

## 2. 应用启动顺序

```text
main.tsx 挂载 App
  → App 查询 /api/v1/auth/status
  → 未初始化：显示首次管理员表单
  → 已初始化：显示登录表单
  → 登录成功：创建 WorkspaceApp
  → 并行加载健康、事件、设置、capabilities、诊断和当前方法
  → 根据用户权限生成导航
  → 根据 target.page 和 target.view 分派页面
```

`WorkspaceApp` 的 `target` 同时保存页面、导航键和内部视图。当前实现没有使用 React Router，因此页面切换不是 URL 路由变化。阅读活动高亮问题时，必须同时查看 `target`、`entryForPage()` 和页面的 `onViewChange()`。

## 3. API 适配边界

R4 已将原 api.ts 拆分，入口与职责如下：

1. [`api/index.ts`](../../app/frontend/src/api/index.ts) 只组合已有 `api` 对象并导出兼容类型/函数，页面仍可从 `./api` 导入。
2. `api/<business>.ts` 放对应业务的请求和类型；跨业务类型使用 `import type`，内部不反向导入 index。
3. [`api/client.ts`](../../app/frontend/src/api/client.ts) 包含 `ApiError`、`requestRaw()`、`request()`；[`api/events.ts`](../../app/frontend/src/api/events.ts) 生成 WebSocket URL。
4. [`platform/runtime.ts`](../../app/frontend/src/platform/runtime.ts) 缓存桌面握手；[`platform/files.ts`](../../app/frontend/src/platform/files.ts) 包含文件保存、旧目录选择与浏览器下载回退。

桌面模式下，`desktopRuntime()` 通过 Tauri 命令取得随机 `api_base` 与一次性进程密钥；`requestRaw()` 自动附加 `X-GeoSpectrum-Process-Key`。浏览器开发模式没有这次握手，使用相对路径。

`ApiError` 会读取后端 `detail.code/detail.message`，把结构化错误转换为界面可用异常。页面应显示错误，不应自己重新解析响应体。

## 4. 导航的两层判断

[`navigation.ts`](../../app/frontend/src/navigation.ts) 有两个不同层次：

- `navigationEntries()` 按用户权限过滤入口。无权读取的入口根本不显示。
- `navigationAvailability()` 判断已获授权入口当前是否可用，例如是否存在已发布当前方法、方法是否暂停、是否启用全时保存。

运行条件只是界面反馈，不能替代后端授权与状态校验。新增导航入口时，源头在后端 `modules/manifest.py`，前端只负责解释清单。

## 5. 页面组织

页面已全部归入 `pages/`；方法页专用面板在 `pages/methods/`，三类迁移页在 `pages/migration/`。旧谱图视图等已有代码也被保留，没有因名称含 Legacy 而删除。独立页面仍通过以下属性接入：

- `token`：Bearer 会话令牌。
- `canWrite/canExecute/canExport`：根据权限计算的界面能力。
- `initialView/onViewChange`：导航入口与页面内部标签同步。
- `onToast`：统一消息提示。

复杂页面一般采用“加载列表 → 选择实体 → 编辑草稿 → 调用 API → 重新加载详情”的模式。页面本身不应实现后端算法，也不应直接访问 SQLite、文件系统或串口。

## 6. 数值输入为何单独封装

项目禁止业务页面直接使用原生 `type="number"`。原因是原生数值输入在清空时容易被 `Number('')` 转为零，破坏“正在编辑但尚未提交”的状态。

`NumericInput` 使用字符串编辑态：

- 允许 `-`、`.`、指数等中间状态继续输入。
- Enter 时执行完整校验。
- Escape 恢复上次有效值。
- 必填空值保持空白并显示错误，不写入零。
- 所有页面共享相同的最小值、最大值和步长判定。

相关测试是 `tests/frontend_numeric_input.test.mjs` 和 `tests/test_architecture.py` 中的使用约束。

## 7. 文件保存

前端生成的 PDF、CSV、TXT、LOG、SAM 统一调用 `saveFile()`：

- Tauri 模式：字节传给 Rust，校验后显示原生“另存为”。
- 浏览器模式：创建一次对象 URL 并触发标准下载。

页面内不得再次直接创建 `<a download>`，否则会绕过桌面白名单和统一取消分支。后端直接写指定输出目录的 S18/S19 导出属于另一条流程。

## 8. 推荐阅读与验证

建议顺序：`main.tsx` → `App` 登录分支 → `WorkspaceApp` → `navigation.ts` → `api/client.ts` 与对应业务请求 → 一个独立页面 → 对应后端模块。

验证命令：

```powershell
cd app
npm.cmd --prefix frontend test
npm.cmd run frontend:build
python -m pytest -p no:cacheprovider tests/test_architecture.py
```
