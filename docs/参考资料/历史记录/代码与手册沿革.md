# 代码与手册沿革

## 04_方法谱线与打印_methods

### 2026-09-14 打印结构更新

`method_printing/service.py` 保留设置、方法快照、预览入口、打印任务及审计流程；`document.py` 组织文档行和分页；`rendering.py` 管理字体及 HTML/PDF 渲染。D1 已将打印机适配移到 [`backend/printing/`](../../../app/backend/printing/__init__.py)，方法和报告共同调用 `SystemPrinters.printers()` 与公开的 `dispatch_pdf()`。原私有调度转发已移除；方法服务的 `printers()` 仍供方法 API 使用。

打印仍先保存 PDF 和渲染输入、登记任务，再调度打印机。调度失败保留文件并登记失败，不改默认设置。

### 2026-09-14 内部解耦更新

`Runtime.method_print_service()` 显式传入方法服务和公共打印适配。`methods/snapshots.py` 的公开快照读取绑定原事务，区分打印最新草稿、指定版本与分析已发布版本，消费者不获取 sqlite3.Row。`service.prepare()` 将原请求模型转为内部 `PrintSettings`；`document.py` 的行组织/分页只使用内部数据，不再导入请求模型或 ReportLab。`rendering.py` 继续负责字体和 HTML/PDF。HTTP 校验与默认设置保持。

### 2026-09-29 谱线版本编辑边界

谱线的 create/update/delete/reorder 继续在一个外层写事务中执行。`MethodService.bind_line_editor(db)` 返回 [MethodLineEditor](../../../app/backend/modules/methods/line_editing.py)：load 提供普通草稿数据，save 统一创建方法版本、更新时间、写入谱线审计并装配方法返回值。谱线服务保留操作规则和先行校验，不再自行更新方法表或调用版本写入私有入口。其他存量几何私有依赖本次未清除。

### 2026-09-29 职责拆分后的阅读入口

方法条件由 `pages/methods/MethodIdentity.tsx`、`MethodGeometry.tsx`、`MethodExcitation.tsx`、`MethodAngles.tsx`、`MethodQuality.tsx` 呈现，`MethodsPage` 持有唯一条件草稿、方法选择、保存和错误状态。`MethodAngles` 将转角和存储方式放在同一行，统一保存方法草稿；原高级存储组件已移除。界面保存时仍沿用 `angle_exposures` 兼容结构，但在提交前将各项 `start_frame/end_frame` 设为1至总帧数，避免隐藏的旧自定义范围继续裁剪新配置；只生成新草稿，不改写已有发布快照，其他API调用方保持旧语义。谱线页没有采集存储表，`SpectralLineEditor` 顶部独立展示“谱线曝光区间”；`SpectralLinesPanel` 保留谱线草稿、创建/保存请求身份与选中项，列表在 `SpectralLineList.tsx`，纯草稿转换及选项在 `spectralLineDraft.tsx`。

### 2026-10-15 曝光配置职责

方法条件新增可选 `exposure_mode`（`simple_mean` / `line_interval`），新建方法默认简单均值。历史版本未声明时仍按原逐线/legacy标志解释，已发布JSON和哈希不变。方法参数的区间曝光复选框控制模式；谱线集合API附带同版本的模式与总帧数，逐线编辑限制1基闭区间且至少两帧，关闭时停用但保留值。完整区间缺省为1到总帧数。

`exposure_interval()`统一向即时测量、正式分析与重算提供有效区间；`AcquisitionRepository`按绑定版本决定普通样品的平均/全时保存，区间模式拒绝缺少方法总帧数的任务。旧PDT重算和参数预览使用同一模式解释；逐转角存储方式在方法表中维护，新界面保存的范围固定为完整采集帧。谱线保存后保留当前已完成的检测状态，避免非几何参数修改后按钮停留在检测中。

## 12_样品采集_acquisition

### 2026-09-14 已有采集记录导入边界

[`acquisition_import.py`](../../../app/backend/modules/acquisition_import.py) 属于采集模块，提供已有帧记录的事务内导入。`ImportedAcquisition` / `ImportedBand` 描述输入，`AcquisitionRecordImporter.bind()` 绑定已有连接，`import_record()` 写入采集任务、样品、谱带和逐帧记录。它不创建 Database、不获得第二个写锁、不独立提交；后处理转换工作单元负责统一提交与回滚。原设备采集状态机及服务生命周期未修改。

### 2026-09-29 职责拆分后的阅读入口

2026-10-15：`SampleAcquisitionPage` 与 `EvaporationAcquisitionPage` 固定各自任务类型，组合独立业务表单。`AcquisitionConditionFields` 共用设备和时间字段；`AcquisitionWorkspace` 共用控制、请求归属保护、监控、谱图与消息。即时定量和异常样品处置仅在样品页显示。

`GET /api/v1/acquisitions/tasks?task_kind=sample|evaporation` 在分页之前筛选类型，省略参数保留原混合列表。已有任务仍在原表中，无需迁移或重建；两个入口共用既有采集权限和当前方法门禁。

`acquisition/service.py` 保留 start/step/pause/resume/stop/fail/close、重复推进以及任务锁和适配器字典；`repository.py::AcquisitionRepository` 拥有任务/样品查询与装配、创建、帧存储、完成结果、区间及命名。存储方法继续接收控制流程持有的原连接，不独立提交外层事务。`simulation.py::_seeded_acquisition_event` 生成确定性模拟帧，`codec.py` 保留 uint16/float32 编解码与 average_points。公开 `get_task` 供 API 查询，路由不再调用私有 `_task_dict`。前端 `SampleAcquisitionForm/Monitor/Results` 从父页接收状态与回调；自动推进计时器现由共用的 `AcquisitionWorkspace` 管理。

## 15_分析与标准曲线_analysis

### 2026-09-14 内部解耦更新

`Runtime.analysis_service()` 显式注入方法服务；分析服务与仓储通过 `bind_snapshots()` 在原连接读取固定版本，不直接查询方法表。创建运行要求已发布版本，运行读取使用已固定版本，不随最新草稿变化。后处理通过 `analysis/contracts.py` 的小型契约调用分析。几何换算仍使用方法服务的 `_layout`、`_dispersion`、`_reference_position`，属于本轮之外的剩余私有依赖。

### 2026-09-29 职责拆分后的阅读入口

分析运行服务现在调用 `inputs.py::AnalysisInputs.prepare_run` 在原创建事务中验证样品、方法版本并组织输入快照；`AnalysisInputs.candidate` 读取/校验谱带和历史逐线结果，再调用 `candidate.py::calculate_candidate`。候选数值函数只接受普通字典、数值、数组，不接收 SQLite 或请求模型；内标有效性和数值错误顺序保持。`rules.py` 拥有 `_operational_lines`、`_analysis_lines` 与基于普通 QC 分组的 `_base_curve_points`，仓储只查询并交给这些规则。原算法、质控、曲线、打印服务继续复用。前端运行表单、干预、原始结果、质控、曲线、标准点及样品结果分别进入 `AnalysisRunForm/Intervention/RawResults/Quality/Curves/Standards/Samples`，`CurveChart.tsx` 独立；当前运行、请求身份、自动推进及草稿由父页统一拥有。

## 16_后处理_postprocessing

### 2026-09-14 结构更新

`postprocessing/` 的 `service.py` 保留公开调用入口；`repository.py` 负责来源查询、区间读取与记录编解码；`conversion.py` 负责 EDT 转换与事务协调；`recalculation.py` 负责固定版本重算；`exporting.py` 负责矩阵构建、格式编码和原子替换；`serialization.py`、`errors.py` 保存共用序列化与错误类型。小文件整理后，原 codec.py 的两个函数已收回 repository.py，原 conversion_uow.py 的事务类型已收回 conversion.py。

转换的业务写入与审计仍在同一事务。导出保持先写文件、再登记数据库的原顺序，不提供文件与数据库之间的整体事务。文件替换失败时，已有文件保留且临时文件清理；对应失败注入测试已通过。

### 2026-09-14 内部解耦更新

Runtime 向后处理传入方法服务、分析契约实现和采集导入能力。重算全程使用同一个分析对象，方法查询通过公开快照，选项列表批量获取版本信息。`conversion.py` 中的 ConversionUnitOfWork 将转换存储与采集导入绑定同一连接；`acquisition_import.py` 负责采集表及帧记录写入，不能独立提交。中途谱带/审计失败整体回滚。

`recalculation.py` 保留格式/档案检查、JSON/BLOB 解码和流程编排，`legacy_calculation.py` 使用 `LegacyIntensity`、方法谱线及曲线参数做纯数值计算。重算与 EDT 转换的事务语义不同：重算先提交分析任务，再登记后处理结果；最终审计失败会留下已完成的分析任务，不能把它当作整体事务。

## 17_报告_reports

### 2026-09-29 分析结果输入边界

Runtime 显式向报告注入 AnalysisService。报告在原事务内调用 `bind_report_inputs(db)`，通过 [AnalysisReportReader](../../../app/backend/modules/analysis/report_inputs.py) 读取运行、质控/合并/曲线快照及方法版本数据。报告不再直接查询分析和方法内部表；完成状态、过期结果拒绝、筛选、舍入与输出仍由报告服务负责。读取器不新开连接或提交，返回普通数据；原未使用的样品查询已去除。

### 2026-09-29 职责拆分后的阅读入口

报告入口改为 `reports/service.py::ReportService`，保留模型准入、版本、确认、文件发布、打印调度与数据库记账。`reports/rendering.py` 拥有表头/表格、TXT/CSV/Excel 编码、PDF 和 HTML 呈现，只消费冻结报告数据，不访问分析库；`values.py` 保留错误及稳定 JSON/哈希。M2 的 AnalysisReportReader 仍是报告输入边界。

## 19_前端架构

### 2026-09-29 职责拆分后的阅读入口

## 20_数据库与API装配

### 2026-09-14 所选依赖的显式装配

Runtime 的方法打印、分析、报告和后处理工厂显式传入各自依赖，构造器不再隐式创建所选跨模块服务。后处理的一次重算使用同一个分析依赖；每次服务工厂调用仍创建本次需要的无状态对象，设备服务的 Runtime 内缓存和事件队列不变。独立测试可以传入受控分析实现，正式工具可以通过 Runtime 工厂构造完整服务。
