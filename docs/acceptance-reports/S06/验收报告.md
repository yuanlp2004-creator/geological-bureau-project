## 事实依据与兼容处理

- 旧库表按 `MTD_PRIM`、`MTD_BURN`、`MTD_WSTC`、`LINES`、`WSTC`、`USER` 读取；样例计数与 S00 基线一致。
- `Stds` 按旧版 `TStd` 的 14 字节 packed 结构解析，实际覆盖 700 字节（50 条）与 224 字节（16 条）两种 BLOB；每个 BLOB 均核对原始长度和 SHA-256，并保留 base64 与解析证据。
- 旧谱线类型 `0/1/2` 分别迁移为分析线、内标线和定位线；`InterWave`、`AlignWave` 按同方法波长与允许类型配对，提交前由当前谱线规则再次校验。
- 每个方法的 `MTD_WSTC` 标量与 3 个 BLOB 必须和同名 `WSTC` 曲线完全对应；不一致会终止暂存。
- 旧方法没有当前模型的转角区间字段，因此按完整采样帧范围生成一个平均区间并在报告中明示。旧 `AllowCcdDrift` 是漂移诊断阈值，不直接冒充当前谱线边界禁入宽度；原值保留在配置快照中。
- `DIRECT.CFG/OPT` 以原始 INI 分区和规范化字段双份保存为非激活快照，不自动覆盖当前设备配置。

事实核对来源：`docs/s00-baseline/formats-and-protocols.md`、`docs/s00-baseline/risks-and-decisions.md`、`Spec Source/Source/Common/uMethod.pas`、`uDbPack.pas`、`uConfigs.pas`、`uOptions.pas` 以及 `Spec2.02/` 实际样例。未把 `UI测试/` 作为业务、接口或架构依据。

## 原子性与幂等

- 暂存阶段只写迁移任务和报告，不写正式方法、版本、CCD、色散或配置目标表。
- 提交在一个 SQLite 写事务中创建所有目标实体；测试在首个方法写入后注入异常，确认方法、版本、CCD、色散、配置和实体映射全部回滚，仅迁移任务以独立事务记录稳定错误码。
- 源集合指纹由 3 个源文件内容哈希组成；相同内容再次暂存直接返回已提交报告。目标映射表另有 `(source_sha256, entity_type, legacy_key)` 唯一约束。
- 提交前再次核对三份源文件的路径、大小、修改时间和 SHA-256，暂存后发生变化会要求重新暂存。

## 缺少 Jet 的诊断

- 读取器诊断返回稳定错误码 `legacy_reader_unavailable`，说明仅旧版迁移不可用。
- 缺少读取器的自动化场景仍可启动 FastAPI，并通过 `/health`；读取器不会在应用生命周期启动阶段执行。
- 正式工程提供 .NET 8 `win-x86` 源码；当前机器没有 .NET SDK 和 x86 .NET 运行时，因此未生成该可执行文件。验收使用同一 JSON 契约的 32 位 Windows PowerShell 实现，实测进程为 32-bit 且 Jet 4.0 可用。
