## 4. 实现边界

- 产品实现只进入 `app/`；不更换 React、图标或图表库，不修改算法、设备协议、数据库、API、权限模型、迁移解析和报告模板。
- 用页面根类限定样式，集中复用视觉变量；避免通过全局覆盖让旧页面或已改三页产生意外变化。不顺带拆分全部业务组件或重写状态管理。
- 表单折叠、单栏/双栏切换需保留组件与编辑状态；不因用户只是收起列表而清空选择、卸载采集轮询或改变实时显示。
- 只展示已有数据。任务栏若已有数据不足以表达百分比，就显示现有状态/帧数，不虚构进度；新增统计、筛选、搜索、全局任务中心不作为本计划隐含功能。
- F-06 固定状态准确性、谱图结果模式初始化等已登记功能问题仍独立处理。阶段编号和装饰文字可以清理，模拟/真实、未接入、失败与安全提示不得清理掉。
- 本计划不要求用户为了截图修改 Windows 显示设置。未实测的系统缩放组合记录为未验证，不把浏览器分辨率等同于系统缩放。

## 5. 验收与完成标准

### 每页的最小检查

1. 记录实际页面与子视图、改前/改后代表截图、主要布局决策；18 页及公共界面逐项标记待做/已实现/已验证，不能以“全局 CSS 已更新”代替逐页覆盖。
2. 至少覆盖正常有数据和无数据状态；采集/校准补运行中与失败状态；迁移补读取失败；权限页补无写权限；表单补非法数值及保存失败保留输入。
3. 当前对象、重要状态和核心操作在首屏可找到。新建表单收起后，主区不得保留原表单高度；展开失败时错误与对应字段可定位。折叠列表不改变任务或方法的运行状态。
4. 主体不被两层页内列表挤压；宽表可在自身区域滚动；图表不得畸变。任务栏展开/收起均保留主要操作，展开入口可由键盘到达。
5. 长中文名、长路径、哈希、多行错误、选中/禁用状态清楚；不得仅靠颜色表达异常；按 [UI 视觉规范](UI_VISUAL_REFINEMENT_PLAN.md) 检查字号、配色、焦点与对比度目标。
