## 4. 已确认根因与修改边界

### BF-01 默认采样周期非法

已确认根因：`SampleAcquisitionPage` 初始值为 `1`，输入控件却以 `0.01` 为步进基准并设置 `step=0.1`，浏览器因此判定 `1` 为 `stepMismatch`。原生表单校验阻止提交，但页面没有将原因转成业务提示。

修改要求：

- 采集页的默认值、步进和允许范围必须与后端采集契约及所选已发布方法保持一致，且默认 `1` 必须合法。
- 若样品采集和蒸发采集允许范围不同，按任务类型显示对应约束，不用一个不匹配的通用步进。
- 创建前执行显式校验并显示中文字段错误，不能仅依赖浏览器焦点变化。
- 后端继续拒绝非有限值、非正值和超范围值；前端约束不能替代 API 校验。

验收：保持所有默认值时可成功创建任务；边界内小数可提交；零、负数、超范围值和非步进值按最终契约明确拒绝并显示中文原因。

### BF-02 管理员缺少“关于与诊断”

已确认根因：`ABOUT_MANIFEST` 要求 `about.read`，但 `system_administrator` 内置权限未包含该权限；管理员自动扩展逻辑又只合并 `s21-` 模块权限。

修改要求：

- 明确四类内置角色的“关于与诊断”可见矩阵；系统管理员必须拥有 `about.read`。
- 同时修复新库初始化和已有库升级，升级必须幂等，不能只修改首次 bootstrap 默认值。
- 权限仍由模块清单驱动；不得在前端为管理员硬编码放行。
- 保留未知角色和自定义角色的最小权限，不无条件向所有角色扩权。

验收：全新数据库和旧数据库升级后，系统管理员均显示并能打开 28/28 个预期入口；直接请求 `/about` 和相关 API 返回成功；无权限角色继续隐藏入口并在直接请求时返回 403。

### BF-03 软件设置非法值被持久化

已确认根因：设置页保存按钮没有走表单校验，`SettingsPatch` 的嵌套分组使用 `dict[str, Any]`，服务层只检查键名、不检查每个值的类型与范围。

修改要求：

- 为 `directories`、`logging`、`display`、`printing`、`time` 建立明确的嵌套请求模型，集中定义枚举、类型和边界。
- `retention_days` 至少为 1；`max_bytes`、主题、密度、日志级别、纸张和时区使用与界面一致的约束。
- API 对非法值返回稳定的 422 错误结构；不得写入数据库，不得生成“保存成功”提示或成功审计。
- 前端保存前展示字段级中文错误；已有数据库若存在非法设置，读取时安全回退到默认值并记录可审计的修复/告警，不静默继续使用非法值。

验收：`0`、负数、越界值、错误类型和未知枚举均不能持久化；合法边界值保存、重启和重新进入页面后保持一致。

### BF-04 队列重复次数显示与执行不一致

已确认根因：选择队列时禁用了本地 `repeatCount` 输入，但没有把选中队列项的 `repeats` 映射到显示值；后端实际会使用队列项值覆盖请求值。

修改要求：

- 选中队列项后，重复次数显示为队列派生值，并标明“来自队列、不可在此修改”。
- 未选择队列时恢复可编辑的临时样品重复次数。
- 切换队列、队列项或临时样号时重置派生状态，避免显示上一个样品的次数。
- 请求负载与界面显示一致；即使后端仍以队列为权威，也不要发送误导性的本地默认值。

验收：队列项分别设置 1、3、10 次时，创建前显示值和任务详情中的实际 `repeat_count` 完全一致；切回临时样号后输入重新可编辑。

### BF-05 隐藏目录输入可聚焦且无标签

已确认根因：透明文件输入仅通过尺寸、透明度和 `pointer-events` 隐藏，仍保留在可访问性树和 Tab 顺序中。

修改要求：

- 将代理文件输入从视觉、Tab 顺序和可访问性树中移除，同时保留由具名“选择目录”按钮触发的能力。
- 目录按钮保留明确的可访问名称和焦点状态。
- 浏览器开发模式与 Tauri 原生目录选择均需回归，不能因隐藏方式改变而失效。

验收：Tab 遍历设置页时不会进入不可见控件；可访问性树不再出现孤立的 `Choose File`；鼠标和键盘仍能通过“选择目录”按钮打开选择器。

### BF-06 登录失败消息未本地化

已确认根因：后端返回英文自由文本，前端直接显示 `error.message`。

修改要求：

- 登录失败返回稳定错误码，例如 `auth_invalid_credentials`；不得区分“用户不存在”和“密码错误”。
- 前端将该错误码映射为统一中文提示“用户名或密码错误”。
- 未识别错误码显示安全的中文兜底消息，同时保留开发诊断所需的非敏感错误码。

验收：不存在的用户和错误密码显示相同中文提示；正确登录不受影响；响应和界面均不泄露账户是否存在。

### BF-07 数值输入清空时自动变为零

已确认根因：多个受控数字输入在 `onChange` 中立即调用 `Number(event.target.value)`；空字符串被转换为零并立即写回。现有 `EmptyableNumberInput` 只覆盖部分页面，且空值失焦时直接恢复旧值，没有形成统一的提交规则。

修改要求：

- 抽取一个前端通用数值输入组件，编辑态保存字符串，提交态再解析为数字；不在每个页面重复实现空值转换。
- 编辑期间允许 `''`、负号开头和尚未完成的小数等中间状态；只有完整有限数字才能写入业务状态。
- 必填字段在 Enter、失焦或提交时为空，应保留空态并显示“必填”错误；可选字段提交为空时写入 `null/undefined`，不能写入零。
- Enter 提交当前合法值，Escape 恢复进入编辑前的值；非法或越界内容保留供用户修改并显示错误，不静默截断或回填。
- `0` 只有在用户明确输入时才作为零提交；允许零的字段和最小为 1 的字段分别按领域规则校验。
- 迁移所有可编辑的 `type=number` 文本框；下拉框、range 控件和只读数值显示不纳入迁移。

优先覆盖：方法条件、采集任务、色散任务、分析慢进、汞灯校准、自动转角、后处理和软件设置。

验收：对初始值 `1` 执行全选、删除、输入 `25`、回车，过程依次显示空、`2`、`25`，不得闪现或保留前导 `0`；删除后回车显示必填错误而不是 `0`；显式输入 `0` 时仅在允许零的字段通过。

- 任一默认主流程仍需手工绕过、API 仍可写入非法设置、管理员入口仍缺失或数值清空仍写零，批次状态为 `failed`，不得请求确认。

- 设置清理只处理已确认非法键值，不重置用户其他合法偏好。
- 通用数值组件迁移若导致某领域的零值语义不明确，暂停该字段迁移并回到对应 schema/业务规则核对，不用统一 `Math.max` 掩盖差异。
