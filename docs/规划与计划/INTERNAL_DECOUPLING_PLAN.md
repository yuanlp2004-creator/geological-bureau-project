## 3. 组织原则与依赖方向

- `runtime.py` 作为应用装配入口，创建并连接跨模块服务；模块内部对象可以由本模块服务组合，不要求所有对象都提升到 Runtime。
- 业务模块调用其他模块的公开应用接口，接口返回明确的数据结构，不泄漏 sqlite3.Row、SQL 或表名。
- 仅在需要替换依赖或约束跨模块契约时使用小型 Protocol；按能力命名，避免一个包含全部服务的上下文对象。
- `service.py` 承担流程编排，`repository.py` 承担本模块存储，`contracts.py` 按实际需要定义契约，纯算法按业务命名。现有目录不强制再套 domain/application 层级。
- 通用打印适配拟放 `backend/printing/`，由 Runtime 和应用服务使用；该目录不依赖 methods、reports、FastAPI 或 Database。实际实施时再创建必要文件。
- 公共契约属于提供能力的模块；只有被证明稳定且跨领域复用的技术能力才提取到公共位置。禁止扩大成万能 common/utils 包。

### D1：打印能力独立

范围：method_printing/printers.py、method_printing/service.py、reports.py 及其调用者、测试。

1. 将系统打印机枚举、虚拟打印机标识、系统 PDF 调度移到独立打印能力中，提供公开方法。
2. 方法打印和报告都依赖该能力，报告不再构造 MethodPrintService 或调用它的私有调度入口。
3. 方法/报告各自保留文档生成、任务记录、错误转换与审计，不把这些业务流程移到公共打印层。
4. 检索现有消费者后决定兼容转发是否必要；若保留，列出调用者和移除条件，不继续新增旧入口调用。

验收：打印能力不导入业务模块或数据库；方法与报告的打印机列表、虚拟打印输出保持；系统调度失败仍保留原有产物、状态与错误，默认设置不变；原预览/PDF 字段与分页不变。复用 test_method_printing.py、test_s19_reports.py，补充报告侧调度失败边界（如现有测试未覆盖）。

### D2：依赖统一装配

范围：Runtime，后处理到分析的调用，分析/方法打印到方法服务的构造，以及 D1 打印适配的装配。暂不改设备服务生命周期和其他迁移模块。

1. 将所选跨模块服务通过显式构造参数注入；后处理重算使用同一明确的分析依赖完成原有调用序列。
2. Runtime 负责生产装配；测试可以直接传入受控依赖。检索测试、脚本及冻结入口的构造调用并一起迁移。
3. 默认不在业务构造函数中偷偷重建依赖；确需保留旧构造方式时，使用明确兼容入口并登记期限。
4. 保持应用之间的隔离和服务原有生命周期。无状态服务不因注入自动变为全局单例，设备连接与事件队列不共享到其他 Runtime。

验收：选定业务流程不再内部构造跨模块服务；受控分析依赖可验证 create/start/step 顺序和失败传播；两个 Runtime 不串数据库或状态；test_runtime_isolation.py、分析与后处理回归通过。此阶段只改装配，不移动 SQL 或事务。

### D3a：公开方法版本快照

范围：方法模块的公开读取接口，方法打印、分析、后处理三个消费者。其他跨表查询列入后续清单。

1. 定义所需的最小快照数据：方法标识、状态、版本标识/编号、发布状态、条件与谱线。返回稳定值，不返回数据库行。
2. 明确“最新版本”“指定版本”“仅已发布版本”的不同读取语义，不将打印草稿与分析已发布版本混为一类。
3. 用公开接口替换三个消费者的目标方法表读取与 _latest_row/_version_dict 调用，保留各自原有 HTTP 错误和字段。
4. 在原先已有事务的读取路径中，保持相同读取时点和一致性；需要共享事务时使用应用层事务绑定能力，调用者不取得方法仓储私有入口。

验收：目标消费者不再直接读方法表或上述私有方法；版本缺失、草稿限制、指定旧版本等边界不变；分析与打印始终使用明确版本。对受影响查询检查结果等价与调用次数，避免逐行重复读取。

### D3b：采集记录的事务内导入接口

范围：EDT 转换中 acquisition_tasks、acquisition_samples、acquisition_sample_bands 的写入职责；不调整硬件采集状态机。

1. 在采集模块提供明确的“导入已有采集记录”应用能力，接收经过定义的元数据与谱带数据。
2. 原后处理转换服务保留批次协调和转换记录；采集模块负责自身记录的 SQL 与结构约束。
3. 使用一次工作单元/事务上下文绑定相关仓储，由外层转换流程统一提交。被调用能力不得再次调用 Database.write()、独立提交或创建第二个 Database。
4. 技术层可以绑定同一个 SQLite 连接，业务参数不暴露连接或 SQL。只实现此场景所需的事务绑定，不扩展成通用工作流框架。

验收：目标采集表写入不再散落于后处理；转换审计失败或中途谱带写入失败时，采集记录、转换记录及审计整体回滚；成功重试、幂等、CCD 顺序、帧值及外键保持。检查当前非重入写锁下无嵌套写入死锁。

### D4：计算逻辑与外部数据结构分离

范围仅为后处理的旧结果净强度/曲线求值流程，以及方法打印的文档行组织/分页；已有独立 analysis/algorithms.py 优先复用。

1. 应用层完成 sqlite3.Row/JSON 解码，形成内部数据结构；纯计算接收数值与版本参数并返回结果。
2. HTTP 请求模型在边界转换为内部打印设置；API 原校验规则、默认值及报错顺序保持，不复制出另一套不一致的规则。
3. 文档组织/分页与 ReportLab、字体注册、文件保存分开。纯计算不访问 Database、文件、进程或 FastAPI，也不依赖 schemas 中的 HTTP 请求模型。
4. 不统一 legacy_2_0_2 与 modern_v1 算法，不改浮点精度、舍入、排序、背景处理或曲线约束。

验收：纯计算可直接以数据运行；历史重算值与失败边界一致；A4 纵向/A3 横向文档、分页、HTML 保持，固定 PDF 元数据后比较字节；适用的 TXT/CSV/Excel 编码结果保持。优先复用黄金样本，避免仅按新实现生成期望值。
