# GeoSpectrum UI 视觉规范

- 更新日期：2026-09-05。
- 文档职责：统一界面的外观、布局和交互呈现规则，不记录页面完成状态、实施批次或授权范围。

## 1. 设计方向与适用范围

延续深蓝侧栏、浅色工作区和专业仪器软件的视觉风格，让文字清楚、布局紧凑、主次明确。保留明暗主题与舒适/紧凑密度。八组导航及右侧展开方式继续沿用。

项目级视觉参考为 `docs/ui-test-homepage-reference.png`；实际界面以当前前端代码和运行结果为准。历史截图用于对照，不作为当前状态证明。规范适用于字体、颜色、间距、控件、表格、提示、导航外观和图表外围布局；业务规则以根目录 `PLAN.md` 为准。

## 2. 视觉基础

以下数值为设计基准，结合页面密度及实际窗口验证，不机械全局替换。紧凑工具栏中的页面标题可以降低层级，避免重复大标题占据首屏。

| 项目 | 规范 |
|---|---|
| 字体 | 优先 Windows 本地中文字体（如 Microsoft YaHei UI）与系统字体；正常显示不依赖外网字体请求 |
| 字号 | 页面标题 24px，区域标题 16～18px，正文/表单 14px，辅助说明 12px；紧凑表格可用 12～13px，关键业务文字不使用 9～10px |
| 层级与颜色 | 深蓝品牌侧栏、蓝色主操作；正文、次要文字、分隔线形成稳定层级；成功/警告/失败同时有文字或图标，不单靠颜色 |
| 可读性 | 将普通文本对比度至少 4.5:1、关键控件边界/焦点至少 3:1 作为本项目设计验收目标；检查实际背景上的最终配色 |
| 间距 | 使用 4/8/12/16/24/32px 间距档位；常规页面边距 24px，卡片内边距 16～20px，按页面密度调整 |
| 控件 | 舒适模式按钮/输入框约 36px，紧凑模式约 32px；图标统一采用现有 lucide 图标，常规 16～18px |
| 卡片 | 常规圆角 6～8px、细边框、弱阴影；减少卡片内部重复套卡片，使用分组标题和分隔线 |
| 操作 | 每个任务区域明确一个主要操作；次要按钮降低强调，危险操作独立表达，保留既有启用条件 |
| 表格 | 数值右对齐并采用等宽数字，单位明确；统一行高与表头；选中和悬停有区别；长名称可查看完整内容 |
| 提示/弹窗 | 统一标题、正文、图标、按钮和错误区样式；已有错误反馈不能因排版而消失或被遮挡 |
| 滚动 | 主要工作区滚动路径清楚；宽表允许局部横向滚动，避免整个窗口横向滚动；粘性工具栏不得遮挡字段 |

## 3. 布局与信息层级

优先让用户当前要看的状态、图表、结果表和操作进入首屏，避免形成“全局导航 → 对象列表 → 子列表 → 编辑区”的多层横向嵌套，也避免“新建表单在上、正在运行的内容在下”。

| 内容用途 | 默认布局 | 收起与空态规则 |
|---|---|---|
| 需要持续查看状态、频繁切换的任务或会话 | 单个窄侧栏，起始宽度约 240–280px，与主体顶部对齐 | 可收起；收起后保留当前任务名称、状态和展开入口；没有任务时不保留空侧栏 |
| 偶尔切换的方法、设备档案、队列、运行版本 | 顶部带标签的选择器及简要状态 | 长名称可查看完整值；编辑对象与当前运行对象有明确区别 |
| 批量选择、跨行比较的数据 | 主体内的宽表或选择区 | 保留多选；宽表局部横向滚动，不强塞进下拉框 |
| 新建任务、创建报告、编辑档案等低频表单 | 点击明确按钮后在主体内展开 | 首次无数据时直接显示；提交成功后回到新对象；失败保留字段与错误；仅折叠不清空未提交值 |
| 帮助文档的章节目录 | 窄目录栏与阅读区 | 目录本身承担导航任务，可以常驻；小窗口可收起 |
| 诊断详情、哈希、完整日志、协议轨迹 | 摘要加可展开详情 | 当前错误、阻断原因、模拟/真实标识及安全控制始终可见 |

不统一强制所有页面使用左栏。每页最多保留一个常驻的业务侧栏；内部对象层级用顶部选择器、现有页签或主体内表格解决。页标题、当前对象和操作栏尽量合并；减少 Sxx 阶段编号及纯装饰英文，保留有业务意义的单位、格式和协议名称。

折叠与换布局仅改变展示：不得停止轮询、触发采集、隐式切换运行方法、重置编辑内容或改变保存时机。开始、暂停、停止和异常处置保留原有启用条件，主操作对应的任务名称必须清楚。

## 4. 状态、表单与可访问性

- 正常、有数据、加载中、空数据、失败、无权限和运行中禁用状态均有清楚反馈。保留既有操作条件，不用颜色代替状态文字。
- 开始、暂停、停止及异常处置保持可见、可到达；模拟/真实设备、未接入和阻断原因不得藏入折叠详情。
- 输入标签、单位与字段就近排列；错误明确关联字段，长错误允许换行。保存失败保留已填内容，非法数值不得隐式变成零或触发写入。
- 折叠只改变展示；其中的错误必须可发现并能定位到对应字段。当前编辑对象和实际运行对象明确区分。
- 主要按钮、表单、列表展开入口和菜单可由键盘到达，焦点可见，Esc 保持原有行为；纯图标按钮具有中文可访问名称。
- 长中文名称、路径、版本和哈希可查看完整内容，不以截断后的内容替代真实值。诊断信息可降低视觉权重，当前错误不可被弱化或隐藏。

## 5. 图表与窗口适配

- 曲线颜色独立于普通状态色管理，叠加、选中和暗色主题下均可辨认，图例与实际曲线保持一致。
- 图表容器保持正确比例，坐标、采样、计算及导出数据不因布局改变；指针位置与实际数据点对应。缩放、平移、框选、锁线等原有能力保持可用。
- 小窗口优先使用合理换行、分区、折叠和局部滚动，不通过缩小所有字号或隐藏关键按钮解决拥挤。
- 页面无整体横向溢出、重要文字裁切、浮层越界或按钮遮挡；宽表允许自身滚动，粘性区域不遮挡内容。
- 明暗主题和密度分别检查实际配色、边界与焦点。浏览器 CSS 视口与 Windows 系统缩放分开记录，不以画布尺寸冒充真实 DPI 验证。具体尺寸和验证场景由实施计划统一维护。

## 6. 样式实现规则

- 视觉值集中维护，页面专属样式限定根类作用范围；避免多层覆盖、大量 `!important` 和对已完成页面的意外影响。
- 沿用现有 React/TypeScript、图标与图表组件；只在确有重复结构时提取轻量视觉组件，不借样式修改重写业务状态管理。
- 正常字体显示优先使用 Windows 本地中文字体和系统字体，不依赖外网字体请求。
- 外观统一不得改变业务数据、权限、设备状态、报告内容或错误事实。具体实现边界、已登记问题及完成标准见配套实施计划。
